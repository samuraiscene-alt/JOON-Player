# JOON Player

JOON Player는 iPhone / iPad 중심의 개인용 동영상 플레이어 프로젝트입니다.

## 현재 개발 단계

Phase 51 — Phase 50 기능 + 전체 앱 GitHub 쓰기 권한 검증 완료

## 재생 목록

파일 앱에서 여러 영상을 한 번에 선택하면 JOON Player가 선택된 파일들로 현재 세션 재생 목록을 만듭니다.

- 파일 선택기가 반환한 순서를 그대로 재생 순서로 사용합니다.
- 하단 컨트롤에 **이전 영상 / 현재 순번 / 다음 영상**이 표시됩니다.
- 상단의 목록 아이콘을 누르면 전체 재생 목록을 열고 원하는 영상을 바로 선택할 수 있습니다.
- 현재 영상이 끝까지 정상 재생되면 다음 항목이 자동으로 시작됩니다.
- 마지막 영상에서는 자동 재생이 종료됩니다.
- 최근 파일에서 한 영상을 열면 재생 목록은 해당 영상 1개로 새로 시작합니다.
- 현재 단계의 재생 목록은 앱 실행 중 사용하는 세션 목록이며 별도 서버나 Supabase에 저장하지 않습니다.
- 목록 화면에서 각 항목의 위/아래 버튼으로 재생 순서를 바꿀 수 있습니다.
- 반복 버튼은 **반복 끔 → 전체 반복 → 한 곡 반복** 순서로 전환됩니다.
- 전체 반복에서는 마지막 영상 다음에 첫 영상으로 이어지고, 이전 버튼도 첫 항목에서 마지막 항목으로 순환합니다.
- 한 곡 반복은 영상이 자연스럽게 끝났을 때 같은 영상을 처음부터 다시 재생합니다.
- 셔플을 켜면 현재 재생 중인 항목의 위치는 유지하면서 나머지 항목 순서를 섞습니다.
- 셔플을 끄면 사용자가 직접 정한 원래 순서로 돌아갑니다.
- 셔플 중에는 수동 순서 변경을 잠가 순서 충돌을 막습니다.
- **현재 재생 목록 저장**에서 이름을 붙여 목록을 기기에 저장할 수 있습니다. 같은 이름을 다시 사용하면 기존 목록을 현재 순서로 교체합니다.
- 저장되는 것은 영상 자체가 아니라 각 파일의 iOS bookmark와 파일명입니다.
- 홈 화면의 **저장된 재생 목록**에서 목록을 다시 불러오면 bookmark를 복원해 현재 세션 재생 목록으로 엽니다.
- 파일이 이동·삭제되어 bookmark를 복원할 수 없는 항목은 자동으로 제외하고, 남은 파일만 재생합니다. 전부 열 수 없으면 해당 저장 목록을 제거하고 안내합니다.
- 저장된 재생 목록은 최근 수정 순으로 최대 20개까지 유지합니다.
- 홈 화면의 저장 목록 오른쪽 **…** 버튼을 누르면 관리 화면을 엽니다.
- 관리 화면의 **…** 메뉴에서 목록 이름을 바꾸거나 저장된 목록 전체를 삭제할 수 있습니다.
- 각 영상 오른쪽 휴지통 버튼으로 그 영상만 저장 목록에서 삭제할 수 있습니다.
- 마지막 남은 영상을 삭제하면 빈 저장 목록은 자동으로 함께 제거됩니다.
- 이름 변경 시 다른 저장 목록과 같은 이름은 허용하지 않습니다.
- 저장 목록이나 항목을 삭제해도 원본 영상 파일은 삭제되지 않습니다.

## Xcode 컴파일 사전 점검

실제 Xcode 프로젝트를 만들기 전에 Swift 6 동시성과 VLCKit API 호환성을 정적 점검했습니다.

- 현재 Podfile의 **VLCKit 4.0.0a24**가 VideoLAN 저장소의 실제 podspec 버전과 일치하는 것을 확인했습니다.
- 해당 소스 스냅샷에서 프레임 이동, 스크린샷, 오디오 딜레이/출력, EQ, 트랙, 챕터, PiP에 필요한 공개 API가 존재하는 것을 확인했습니다.
- VLCKit delegate는 콜백 스레드를 main으로 가정하지 않고 `nonisolated` witness에서 `MainActor`로 넘겨 UI/Published 상태를 수정합니다.
- Swift 6 strict concurrency에서 일반 `deinit`이 main-actor 메서드를 직접 부를 수 없는 문제를 제거했습니다.
- 상세 점검 기록은 `Docs/PreXcode-Compile-Preflight.md`에 정리했습니다.
- 아직 저장소에 실제 Xcode 프로젝트가 없으므로 **컴파일 성공을 확정한 단계는 아닙니다.** 최종 판정은 Mac/Xcode에서 진행합니다.

## 임시 파일과 리소스 정리

스크린샷, 자르기, 복구처럼 임시 디렉터리에 결과를 만드는 기능의 수명 주기를 정리했습니다.

- 현재 장면 스크린샷 작업은 별도 Task로 추적하고 재생 화면이 사라지면 취소합니다.
- 스크린샷 파일 생성 대기 중 Task가 취소되면 이미 만들어졌거나 부분 생성된 PNG를 즉시 삭제합니다.
- 취소 직전에 스크린샷 생성이 끝난 경우에도 화면으로 결과를 넘기기 전에 취소 상태를 다시 확인하고 임시 파일을 삭제합니다.
- 빠른/정확 자르기와 영상 복구 결과는 공유 시트가 닫힌 뒤 임시 출력 파일을 자동 삭제합니다. 사용자가 파일 앱이나 사진 등으로 저장한 사본에는 영향을 주지 않습니다.
- 새 자르기/복구 작업을 시작하기 전 이전 임시 결과가 남아 있으면 먼저 정리합니다.
- 자르기 작업 중에는 화면을 닫거나 스와이프로 내릴 수 없게 해 원본 접근 권한이 처리 도중 끊기는 상황을 줄였습니다.
- 화면 계층이 예상치 않게 사라지는 경우를 대비해 자르기/복구 Task도 취소 상태를 추적하며, 작업이 뒤늦게 끝나면 결과 임시 파일을 삭제합니다.
- AVFoundation 자르기가 실패하거나 취소되는 경우 부분적으로 만들어진 출력 파일도 즉시 제거합니다.
- PlayerViewModel의 영상 파일과 외부 자막 security-scoped resource 해제는 `releaseCurrentFileAccess()` 한 경로로 통합해 파일 전환·플레이어 종료·deinit에서 같은 순서로 정리합니다.
- FFmpeg 자르기/복구 실패 시 부분 출력 삭제는 기존 서비스 레벨 정리를 그대로 유지합니다.

## 코드 안정성 정리

Phase 43에서는 새 기능을 늘리지 않고 누적된 재생 상태 처리 중 중복과 경계 조건을 정리했습니다.

- 프레임 이동과 현재 장면 스크린샷이 공통으로 요구하는 **영상 출력 준비 상태**를 `hasReadyVideoOutput` 한 곳에서 판단합니다.
- 스크린샷 퀵 액션도 별도 추측 대신 `canCaptureSnapshot`을 사용해 실제 캡처 가능 조건과 UI 활성 조건이 서로 어긋나지 않게 했습니다.
- 챕터 이전/다음 가능 여부를 VLC의 raw chapter index가 0부터 연속된다는 가정으로 계산하지 않습니다.
- 현재 챕터가 `chapterOptions`의 몇 번째 항목인지 먼저 찾고, 실제 앞/뒤 항목의 chapter id를 선택하도록 변경했습니다. 따라서 비연속 chapter id나 목록 순서가 raw id와 다른 경우에도 경계 판정이 더 안전합니다.
- 재생 정보의 파일 확장자 처리에서 `url!` 강제 언래핑을 제거했습니다.
- 파일 크기 읽기도 중첩 Optional을 만들지 않고 URL 리소스 값에서 안전하게 `Int?`로 정리합니다.
- 이번 정리는 재생 기능 자체의 정책이나 사용자 설정값은 변경하지 않습니다.

## 앱 설정 초기화

빠른 설정의 **기타 → 앱 설정 초기화**에서 사용자가 바꾼 앱 전체 기본 설정만 한 번에 되돌릴 수 있습니다.

- 실행 즉시 지워지지 않도록 **확인 경고창**을 먼저 표시합니다.
- 초기화 대상은 **재생 속도 → 1x**, **화면비율 → 원본**, **자막 크기 → 100%**, **자막 위치 → 기본**, **퀵 액션 → 기본 3개 구성**입니다.
- 현재 영상이 열려 있으면 재생 속도·화면비율·자막 크기는 즉시 화면에 반영합니다.
- 자막 위치가 기본이 아니었다면 기존 동작과 동일하게 현재 영상을 같은 시점에서 짧게 다시 열어 기본 위치를 적용합니다.
- 초기화된 값은 `UserDefaults`에도 기본값으로 저장되어 다음 앱 실행에도 유지됩니다.
- **이어보기 위치, 영상별 북마크, 최근 파일, 저장된 재생 목록은 삭제하지 않습니다.**
- 영상별 임시 설정인 오디오 싱크·EQ·A-B 반복 등은 원래부터 새 영상에서 초기화되므로 이 버튼의 삭제 대상 데이터로 취급하지 않습니다.

## 재생 설정 저장 범위

설정마다 성격이 다르기 때문에 모든 값을 무조건 기억하지 않고 **앱 전체 유지 / 현재 실행 유지 / 영상별 유지 / 영상 전환 시 초기화**로 구분합니다.

### 앱을 종료해도 유지

다음 값은 사용자의 기본 취향으로 보고 로컬 `UserDefaults`에 저장합니다.

- **재생 속도**: 0.5x ~ 2.0x. 새 영상과 다음 앱 실행에서도 마지막 선택값을 사용합니다.
- **화면비율**: 원본 / 화면 맞춤 / 화면 채우기. 다음 영상과 다음 앱 실행에서도 유지합니다.
- **자막 크기 / 자막 위치**: 기존과 동일하게 앱 전체 기본값으로 유지합니다.
- **퀵 액션 구성 / 순서**: 사용자가 만든 최대 3개 구성을 유지합니다.

### 앱 실행 중에는 유지하지만 종료 후 복원하지 않음

- **JOON Player 내부 볼륨 / 음소거 상태**는 현재 앱 실행과 영상 전환 중에는 유지합니다.
- iOS의 실제 하드웨어 출력 경로와 시스템 볼륨이 앱 밖에서도 바뀔 수 있으므로 JOON Player의 별도 볼륨 상태는 다음 앱 실행까지 강제로 복원하지 않습니다.
- **15/30/60분 취침 타이머**는 같은 재생 목록 안에서 다음 영상으로 넘어가도 계속 진행하지만 플레이어를 닫거나 앱을 새로 시작하면 종료합니다.

### 같은 영상에 연결해 기억

- **이어보기 위치**는 영상 식별자별로 저장합니다.
- **재생 위치 북마크**도 영상 식별자별로 저장합니다.
- 다른 파일의 이어보기/북마크가 현재 영상에 섞이지 않습니다.

### 새 영상으로 넘어갈 때 초기화

다음 값은 파일마다 필요한 보정값이 다를 수 있어 새 영상을 열 때 기본값으로 되돌립니다.

- **오디오 싱크** → 0.0초
- **오디오 출력 모드** → 기본
- **이퀄라이저 프리셋 / 사용자 밴드 조절** → 끔
- **외부 SRT 연결 / 자막 싱크** → 연결 해제 / 0.0초
- **A-B 반복 구간** → 해제
- 현재 미디어의 **오디오/자막 트랙 선택과 챕터 상태**는 새 파일에서 다시 읽습니다.

이 정책을 코드에서도 `resetMediaScopedPlaybackSettings()`로 한 곳에 모아 새 영상 로드와 플레이어 종료가 같은 기준을 사용하도록 했습니다.

또한 화면을 길게 눌렀을 때의 **임시 2배속**은 이제 저장용 `playbackRate` 값을 변경하지 않고 VLC 엔진에만 잠시 적용합니다. 따라서 임시 2배속 도중에도 사용자가 선택한 1x / 1.25x / 1.5x 같은 기본 속도가 저장값으로 오염되지 않습니다.

## 사용자 퀵 액션

빠른 설정의 **기타 → 퀵 액션**에서 재생 화면에 바로 노출할 기능을 직접 선택할 수 있습니다.

- 퀵 액션은 최대 **3개**까지 선택합니다.
- 선택한 기능은 재생 컨트롤 바로 위의 작은 원형 버튼으로 표시합니다.
- 기본 구성은 **북마크 저장 / 스크린샷 / 다음 프레임**입니다.
- 선택 가능한 기능은 **북마크 저장 / 스크린샷 / 이전 프레임 / 다음 프레임 / 음소거 / PiP**입니다.
- 빠른 설정에서 각 항목을 **위로 / 아래로** 이동해 실제 표시 순서를 바꿀 수 있습니다.
- 필요 없는 항목은 제거할 수 있고, **퀵 액션 추가** 메뉴에서 빈 자리에 다른 기능을 넣습니다.
- **기본 구성으로 복원**을 누르면 초기 세 가지 구성으로 즉시 되돌립니다.
- 선택 결과와 순서는 로컬 `UserDefaults`의 `joonplayer.quick.actions.v1`에 저장되므로 앱을 다시 실행해도 유지됩니다.
- 북마크가 이미 현재 위치에 저장된 경우 해당 북마크 버튼은 채워진 아이콘으로 바뀌고 중복 저장을 막습니다.
- 스크린샷과 프레임 이동은 VLC 영상 출력이 준비된 재생/일시정지 상태에서만 활성화됩니다.
- PiP는 VLCKit의 PiP 컨트롤러가 준비된 경우에만 활성화됩니다.
- 음소거 퀵 액션은 현재 음소거 상태에 따라 스피커 아이콘을 바꾸고 기존 볼륨 피드백을 함께 표시합니다.
- 모든 퀵 액션 버튼은 VoiceOver 레이블과 최소 44pt 터치 영역을 사용합니다.

## 재생 화면 접근성

재생 화면과 빠른 설정의 VoiceOver, 큰 텍스트, 터치 영역을 보강했습니다.

- VoiceOver가 켜져 있으면 영상 위의 더블 탭/드래그/길게 누르기 같은 직접 제스처 레이어를 터치 입력에서 제외하고, 접근 가능한 재생 버튼을 사용하도록 합니다.
- VoiceOver 사용 중에는 가로 전체화면의 3초 자동 숨김을 중지해 재생 컨트롤이 갑자기 사라지지 않게 합니다.
- 재생/일시정지, ±10초 이동, 볼륨, 화면 잠금, 재생 위치 슬라이더, 상단 메뉴 버튼에 명확한 VoiceOver 레이블·현재 값·힌트를 추가했습니다.
- 재생 위치 슬라이더는 현재 시간과 전체 시간을 하나의 접근성 값으로 읽습니다.
- A-B 반복과 취침 타이머 상태도 VoiceOver에서 별도 상태로 확인할 수 있습니다.
- 재생 목록 이전/다음, 챕터 이전/다음, 북마크 삭제처럼 작았던 아이콘 버튼은 최소 **44×44pt** 수준의 터치 영역을 갖도록 확대했습니다.
- 빠른 설정 그룹 헤더는 **접힘/펼쳐짐** 상태와 현재 요약값을 VoiceOver로 읽습니다.
- 접근성 크기의 Dynamic Type에서는 재생 속도, 취침 타이머, 오디오 출력, 자막 위치 같은 가로 선택 버튼을 세로로 배치해 글자 잘림과 좁은 터치 영역을 줄입니다.
- 접근성 큰 글씨에서는 그룹 헤더의 짧은 요약 텍스트를 화면에서 숨기고, VoiceOver 접근성 값에는 계속 포함합니다.
- VoiceOver가 켜진 동안 외장 키보드 단축키는 시스템 접근성 키 조작과 충돌 가능성을 줄이기 위해 일시 비활성화합니다.
- 실제 VoiceOver 포커스 순서와 최대 Dynamic Type 크기에서의 레이아웃은 Mac/Xcode 실기기 단계에서 최종 확인합니다.

## 외장 키보드 단축키

iPad 또는 iPhone에 연결한 하드웨어 키보드로 기본 재생 동작을 바로 조작할 수 있습니다.

- **Space**: 재생 / 일시정지
- **← / →**: 10초 뒤로 / 앞으로
- **↑ / ↓**: JOON Player VLC 볼륨을 5%씩 올리기 / 내리기
- **M**: 음소거 / 음소거 해제
- 좌우 탐색은 화면 더블 탭과 같은 ±10초 피드백을 표시합니다.
- 볼륨과 음소거는 화면 오른쪽의 볼륨 퍼센트 피드백을 짧게 표시합니다.
- 단축키는 재생 컨트롤이 자동으로 숨겨진 상태에서도 동작합니다.
- 화면 잠금 상태에서는 단축키도 함께 비활성화해 잠금 동작과 충돌하지 않게 했습니다.
- 빠른 설정, 볼륨 팝업, 재생 목록, 자르기/복구/재생 정보/공유 시트가 열려 있을 때는 해당 화면의 조작을 방해하지 않도록 단축키를 일시 비활성화합니다.
- UIKit `UIKeyCommand`를 사용해 iOS/iPadOS 하드웨어 키보드 입력을 받고, 각 명령에 discoverability 제목을 제공합니다.
- 실제 키보드 종류와 iPadOS/iOS 시스템 포커스 동작은 Mac/Xcode 실기기 단계에서 최종 확인합니다.

## 빠른 설정 그룹 UI

기능이 늘어나면서 길어진 빠른 설정을 **재생 / 오디오 / 자막 / 기타** 네 그룹으로 정리했습니다.

- 빠른 설정을 열면 기본적으로 **재생** 그룹이 펼쳐집니다.
- 그룹 제목을 누르면 펼치거나 접을 수 있으며, 한 번에 한 그룹만 펼쳐져 작은 iPhone 화면에서도 목록이 과도하게 길어지지 않게 했습니다.
- **재생**: 재생 속도, 프레임 이동, 북마크, A-B 반복, 취침 타이머, 챕터, 화면비율.
- **오디오**: 오디오 트랙, 오디오 싱크, 출력 모드, 이퀄라이저 프리셋/사용자 조절.
- **자막**: 내장 자막 트랙 선택과 외부 SRT 선택/싱크/크기/위치.
- **기타**: PiP, 영상 복구/리먹스, 재생 정보, 현재 장면 스크린샷, 다른 동영상 열기.
- 접힌 그룹 헤더에는 재생 속도·화면비율, 현재 오디오 트랙·출력 모드, 현재 자막 상태 같은 요약을 표시합니다.
- 기존 기능의 동작 자체는 바꾸지 않고 화면 구조만 정리했습니다.

## 오디오 이퀄라이저

빠른 설정의 **이퀄라이저**에서 VLCKit에 포함된 프리셋과 사용자 직접 조절을 모두 사용할 수 있습니다.

- 프리셋 목록은 앱에 이름을 하드코딩하지 않고 `VLCAudioEqualizer.presets`에서 현재 VLCKit이 제공하는 목록을 읽습니다.
- 프리셋을 선택하면 `VLCAudioEqualizer(preset:)`로 새 이퀄라이저를 만들고 현재 플레이어에 즉시 적용합니다.
- 프리셋이 활성화되면 **프리앰프**와 VLCKit이 제공하는 모든 **주파수 밴드** 슬라이더가 나타납니다.
- 프리앰프와 각 밴드는 **-20 dB ~ +20 dB**, 0.5 dB 단위로 직접 조절합니다.
- 프리셋 상태에서 프리앰프나 밴드를 움직이면 프리셋 이름 대신 **사용자 조절** 상태로 전환됩니다.
- **평탄화**는 새 기본 이퀄라이저를 만들어 프리앰프와 모든 밴드를 기본값으로 되돌리되 이퀄라이저 자체는 켜 둡니다.
- **끔**을 선택하면 플레이어의 equalizer를 `nil`로 되돌려 원본 음색으로 재생합니다.
- 주파수와 현재 증폭값은 각 슬라이더 위에 Hz/kHz와 dB로 표시합니다.
- 오디오 트랙을 바꾸거나 자막 위치 변경으로 미디어가 내부 재시작되는 경우에도 현재 프리셋 또는 사용자 조절 이퀄라이저를 다시 적용합니다.
- 새 영상으로 넘어가면 이퀄라이저는 **끔**으로 초기화합니다.
- 이퀄라이저는 재생 출력에만 적용되며 원본 영상/오디오 파일을 수정하지 않습니다.
- 실제 밴드 주파수, 프리셋 이름과 개수는 연결된 VLCKit 버전에 따라 달라질 수 있습니다.

## 오디오 출력 모드

빠른 설정의 **오디오 출력**에서 현재 영상의 소리 채널 방식을 바꿀 수 있습니다.

- **기본**: VLC와 원본 파일의 기본 오디오 출력 방식을 그대로 사용합니다.
- **스테레오**: 좌/우 스테레오 출력을 사용합니다.
- **모노**: 오디오를 모노 출력으로 전환합니다.
- **좌**: 왼쪽 채널 중심으로 출력합니다.
- **우**: 오른쪽 채널 중심으로 출력합니다.
- VLCKit 4의 `audioStereoMode`를 사용하며 `unset / stereo / left / right / mono`에 해당하는 공식 raw value를 적용합니다.
- 오디오 트랙을 바꾸거나 자막 위치 변경으로 현재 미디어를 내부 재시작해도 선택한 출력 모드를 다시 적용합니다.
- 새 영상으로 넘어가면 안전하게 **기본**으로 초기화합니다.
- 이 설정은 재생 출력만 바꾸며 원본 영상이나 오디오 트랙 자체를 수정하지 않습니다.
- 특정 코덱, 다채널 오디오, AirPlay/Bluetooth 출력에서는 실제 채널 동작이 기기/출력 경로에 따라 달라질 수 있으므로 실기기에서 최종 확인합니다.

## 오디오 싱크

빠른 설정의 **오디오 싱크**에서 영상과 소리의 타이밍이 맞지 않는 파일을 재생 중 바로 보정할 수 있습니다.

- **-0.1**을 누르면 소리를 0.1초 앞당깁니다.
- **+0.1**을 누르면 소리를 0.1초 늦춥니다.
- 가운데 현재 값을 누르면 **0.0초**로 즉시 초기화합니다.
- 조절 범위는 **-10초 ~ +10초**이며 0.1초 단위로 변경합니다.
- VLCKit 4의 `currentAudioPlaybackDelay`를 사용하며 내부 단위인 마이크로초로 변환해 적용합니다.
- VLCKit 기준으로 양수는 오디오를 더 늦게 재생하고, 음수는 더 일찍 재생합니다.
- 오디오 트랙을 바꾸더라도 현재 오디오 싱크 값을 다시 적용합니다.
- 자막 위치 변경으로 현재 미디어를 다시 여는 경우에도 오디오 싱크 값을 유지해 다시 적용합니다.
- 새 영상으로 넘어가면 오디오 싱크는 **0.0초**로 초기화됩니다. 영상 파일 자체는 수정하지 않습니다.

## 재생 위치 북마크

빠른 설정의 **북마크**에서 현재 영상의 원하는 시점을 여러 개 저장할 수 있습니다.

- **현재 위치 저장**을 누르면 현재 재생 시간을 북마크로 저장합니다.
- 같은 위치에서 중복 북마크가 쌓이지 않도록 약 0.75초 이내의 기존 북마크가 있으면 추가 버튼이 **현재 위치 저장됨** 상태로 바뀝니다.
- 저장된 시간 항목을 누르면 해당 시점으로 즉시 이동합니다.
- 현재 재생 위치와 가까운 북마크는 재생 아이콘을 채워서 표시합니다.
- 각 북마크는 개별 삭제할 수 있고 **이 영상 북마크 모두 삭제**도 지원합니다.
- 한 영상당 최대 50개를 유지하며 한도를 넘으면 가장 오래 전에 만든 북마크부터 정리합니다.
- 북마크는 영상 파일 자체에 쓰지 않고 iPhone/iPad의 로컬 `UserDefaults`에 저장합니다.
- 영상 식별에는 이어보기와 같은 파일 식별자를 사용하므로 앱을 다시 실행해 같은 파일을 열면 저장한 북마크가 다시 나타납니다.
- 원본 영상 파일은 수정하지 않습니다.

## 프레임 단위 탐색

빠른 설정의 **프레임 이동**에서 현재 영상을 한 프레임씩 앞뒤로 확인할 수 있습니다.

- **이전 프레임 / 다음 프레임** 버튼을 제공합니다.
- VLCKit 4의 `gotoPreviousFrame()` / `gotoNextFrame()`를 사용합니다.
- 영상이 재생 중인 상태에서 프레임 이동을 누르면 VLCKit이 먼저 일시정지한 뒤 한 프레임을 이동합니다.
- 프레임 이동은 영상 출력이 준비된 재생 또는 일시정지 상태에서만 활성화됩니다.
- 다음 프레임 이동은 현재 비디오 출력에서 한 프레임씩 앞으로 진행합니다.
- 이전 프레임은 해당 스트림이 **일시정지 / 탐색 / 속도 제어**를 지원해야 하므로 일부 네트워크 스트림이나 코덱에서는 동작하지 않을 수 있습니다.
- 프레임 단위로 원하는 장면을 맞춘 뒤 기존 **현재 장면 스크린샷** 기능을 사용하면 정밀한 캡처에 활용할 수 있습니다.

## 현재 장면 스크린샷

빠른 설정의 **현재 장면 스크린샷**을 누르면 VLCKit의 현재 비디오 출력 프레임을 PNG 이미지로 만듭니다.

- VLCKit 4의 `saveVideoSnapshot(at:withWidth:andHeight:)`를 사용하고 너비/높이를 0으로 요청해 가능한 경우 원본 프레임 크기로 저장합니다.
- 파일명에는 원본 영상 이름과 현재 재생 시간이 들어가며, 같은 시점에서 여러 번 캡처해도 충돌하지 않도록 짧은 고유값을 붙입니다.
- 캡처가 끝나면 iOS 공유 시트를 열어 사용 가능한 **이미지 저장 / 파일 저장 / 메시지·앱 공유** 동작을 사용자가 선택할 수 있습니다.
- JOON Player가 사진 보관함에 직접 쓰는 방식이 아니므로 캡처 단계에서 사진 접근 권한을 별도로 요구하지 않습니다.
- 공유 시트가 닫히면 앱 임시 폴더의 PNG는 자동으로 삭제합니다. 사용자가 공유 시트에서 저장한 사본에는 영향을 주지 않습니다.
- 영상 출력이 아직 준비되지 않았거나 VLC가 스냅샷 파일을 만들지 못하면 오류를 안내합니다.
- 이 기능은 화면 전체를 찍는 iOS 시스템 스크린샷이 아니라 VLC 비디오 출력의 현재 프레임 캡처입니다. 자막/영상 필터가 결과 이미지에 포함되는 범위는 VLCKit 실제 출력 경로에 따라 실기기에서 확인합니다.

## 재생 정보

빠른 설정의 **재생 정보**에서 현재 영상의 기술 정보를 확인할 수 있습니다.

- 파일명, 컨테이너 확장자, 파일 크기, 전체 재생 시간을 표시합니다.
- 각 비디오 트랙의 **코덱 / 해상도 / FPS / 비트레이트 / 언어**를 가능한 범위에서 표시합니다.
- 각 오디오 트랙의 **코덱 / 채널 수 / 샘플레이트 / 비트레이트 / 언어**를 표시합니다.
- 자막 트랙은 **코덱 / 문자 인코딩 / 언어** 정보를 표시합니다.
- 현재 VLC에서 선택되어 실제 재생에 사용 중인 트랙에는 **사용 중** 표시가 붙습니다.
- 코덱 이름과 트랙 정보는 VLCKit 4가 현재 미디어에서 읽어낸 값을 사용하며, 원본 파일에 정보가 없거나 VLC가 노출하지 않는 항목은 표시하지 않습니다.
- 재생 정보는 읽기 전용이며 원본 영상이나 재생 설정을 변경하지 않습니다.

## 챕터 탐색

빠른 설정의 **챕터**에서 챕터 정보가 들어 있는 영상의 구간을 바로 이동할 수 있습니다.

- VLCKit 4의 현재 title과 `chapterDescriptions(ofTitle:)` 정보를 사용합니다.
- 챕터가 2개 이상일 때 **이전 / 챕터 목록 / 다음** 컨트롤을 표시합니다.
- 챕터 목록에는 각 챕터의 시작 시간과 이름을 함께 표시합니다.
- 이름 정보가 없는 챕터는 **챕터 1**, **챕터 2**처럼 자동 이름을 사용합니다.
- 목록에서 원하는 챕터를 누르면 해당 챕터로 즉시 이동합니다.
- 이전/다음 버튼은 VLCKit의 `previousChapter()` / `nextChapter()`를 사용합니다.
- 재생 위치가 다음 챕터로 넘어가면 현재 챕터 체크 상태도 자동으로 갱신합니다.
- 챕터가 없거나 하나뿐인 일반 영상에서는 이동 컨트롤 대신 챕터가 없다는 안내만 표시합니다.

## 오디오 / 자막 트랙

빠른 설정의 **오디오 / 자막 트랙**에서 현재 영상에 포함된 트랙을 선택할 수 있습니다.

- VLCKit 4의 `audioTracks` / `textTracks` 목록을 사용합니다.
- 오디오 트랙이 여러 개이면 메뉴에서 원하는 언어/트랙을 즉시 선택할 수 있습니다.
- 자막 트랙은 영상에 들어 있는 트랙뿐 아니라 VLC가 현재 입력에 연결해 둔 텍스트 트랙을 표시합니다.
- 자막 트랙 메뉴의 **끔**을 선택하면 모든 텍스트 트랙을 해제합니다.
- 현재 선택된 트랙에는 체크 표시를 보여줍니다.
- 트랙 이름이 비어 있는 파일은 **오디오 1**, **자막 1** 같은 대체 이름을 표시합니다.
- 빠른 설정을 열거나 재생/일시정지 상태가 바뀔 때 트랙 목록과 선택 상태를 다시 읽습니다.
- 외부 SRT 직접 선택 기능은 기존대로 별도 유지되며, 연결된 외부 SRT도 VLC 텍스트 트랙 목록에 나타날 수 있습니다.

## 취침 타이머

빠른 설정의 **취침 타이머**에서 자동 정지 조건을 선택할 수 있습니다.

- **15분 / 30분 / 60분**: 선택한 실제 시간이 지나면 현재 재생 위치를 저장하고 영상을 일시정지합니다.
- **영상 끝**: 현재 영상이 자연스럽게 끝나는 시점에 정지하며, 재생 목록에 다음 영상이 있어도 자동으로 넘어가지 않습니다.
- 시간 타이머는 1초 단위로 남은 시간을 계산하고 빠른 설정에 `MM:SS 후 정지` 형태로 표시합니다.
- 타이머가 활성화되어 있으면 하단 진행 바 왼쪽에 달 아이콘이 표시됩니다.
- **타이머 해제**를 누르면 즉시 취소됩니다.
- 플레이어를 닫으면 타이머도 함께 해제됩니다.
- 재생 목록 안에서 다른 영상으로 자동 이동하거나 사용자가 다음/이전 영상을 선택해도 15/30/60분 타이머는 유지합니다.
- A-B 반복이 켜져 있고 **영상 끝** 타이머를 선택한 경우, 영상이 실제 끝에 도달하지 않는 동안에는 타이머가 발동하지 않습니다.

## A-B 구간 반복

빠른 설정의 **A-B 반복**에서 현재 영상의 특정 구간만 반복해서 볼 수 있습니다.

- 원하는 시작 위치에서 **A 설정**을 누르면 시작점을 저장합니다.
- A보다 최소 0.5초 뒤의 위치에서 **B 설정**을 누르면 반복이 활성화됩니다.
- 재생 위치가 B 지점에 도달하면 자동으로 A 지점으로 돌아가 계속 재생합니다.
- B가 영상 끝과 거의 같은 경우에도 영상 종료 시 재생 목록의 다음 항목으로 넘어가기보다 A 지점으로 다시 돌아가도록 처리합니다.
- A를 다시 설정하면 기존 B는 초기화되므로 새 구간을 안전하게 다시 지정할 수 있습니다.
- **×** 버튼으로 A/B 지점을 모두 해제합니다.
- 다른 영상이나 다른 재생 목록 항목을 열면 A-B 반복은 자동으로 초기화됩니다.
- A-B 반복이 활성화되면 하단 진행 바 왼쪽에 **A-B** 표시가 나타납니다.

## 재생 제스처

재생 화면을 손가락으로 조작할 수 있습니다.

- 화면을 **한 번 탭**하면 기존처럼 재생 컨트롤을 표시하거나 숨깁니다.
- 영상의 **왼쪽 절반을 더블 탭**하면 10초 뒤로 이동합니다.
- 영상의 **오른쪽 절반을 더블 탭**하면 10초 앞으로 이동합니다.
- 더블 탭 직후 해당 방향에 `-10초` / `+10초` 원형 피드백을 약 0.65초 표시합니다.
- 더블 탭은 재생/일시정지 상태를 바꾸지 않고 현재 상태를 그대로 유지합니다.
- 화면 잠금 상태에서는 단일 탭과 더블 탭 제스처 모두 동작하지 않습니다.
- 단일 탭과 더블 탭은 exclusive gesture로 분리해 더블 탭할 때 컨트롤이 함께 켜지거나 꺼지는 것을 막습니다.
- 화면을 **좌우로 드래그**하면 현재 위치를 기준으로 목표 시점을 미리 계산합니다. 오른쪽은 앞으로, 왼쪽은 뒤로 이동합니다.
- 수평 이동이 세로 이동보다 충분히 큰 경우에만 탐색으로 인식해 일반적인 세로 방향 손동작 오인식을 줄입니다.
- 드래그 중에는 중앙에 **목표 시간 / 전체 시간 / ±이동 초 / 진행 바**를 표시합니다.
- 드래그하는 동안에는 실제 재생 위치를 계속 바꾸지 않고, 손을 떼는 순간 한 번만 목표 위치로 이동합니다.
- 수평 드래그는 약 **1pt당 0.12초** 감도로 동작하며 영상의 처음과 끝 범위를 넘지 않도록 제한합니다.
- 수평 드래그도 화면 잠금 상태에서는 동작하지 않습니다.
- 영상이 재생 중일 때 화면을 약 **0.35초 길게 누르면** 임시 2배속이 시작됩니다.
- 손가락을 떼거나 18pt 이상 움직이면 즉시 원래 재생 속도로 돌아옵니다.
- 1.25x, 1.5x처럼 사용자가 이미 다른 속도를 선택해 둔 경우에도 길게 누르기 전 속도를 기억했다가 정확히 복원합니다.
- 일시정지 상태에서는 길게 누르기가 자동으로 재생을 시작하지 않습니다.
- 임시 2배속 중에는 상단에 **2× · 길게 누르는 동안** 피드백을 표시합니다.
- 수평 드래그 탐색을 시작하면 임시 2배속은 즉시 해제되어 두 제스처가 충돌하지 않도록 했습니다.
- 화면 잠금 상태에서는 임시 2배속도 작동하지 않습니다.
- 임시 2배속이 끝나는 순간 손가락을 떼는 동작이 단일 탭으로 잘못 인식되어 컨트롤이 켜지거나 꺼지는 현상을 막기 위해 짧은 탭 억제 구간을 둡니다.
- 수평 탐색이 이미 시작된 상태에서는 길게 누르기 2배속이 활성화되지 않으며, 반대로 수평 탐색이 시작되면 임시 2배속을 즉시 종료합니다.
- 길게 누르기가 끝난 뒤 가로 재생 중이라면 기존 3초 자동 숨김 동작을 다시 예약합니다.
- 더블 탭 피드백 시간, 수평 탐색 감도, 길게 누르기 시간과 허용 이동 거리 등은 `PlaybackGestureTuning` 한 곳에서 관리해 실기기 테스트 후 빠르게 조정할 수 있습니다.
- 화면 **왼쪽 절반을 위/아래로 드래그**하면 iPhone/iPad의 화면 밝기를 조절합니다. 위로 올리면 밝아지고 아래로 내리면 어두워집니다.
- 화면 **오른쪽 절반을 위/아래로 드래그**하면 JOON Player의 VLC 재생 볼륨을 조절합니다. iOS의 하드웨어/시스템 볼륨 자체를 강제로 바꾸는 방식은 아닙니다.
- 세로 드래그 중에는 해당 측면에 **밝기 또는 볼륨 아이콘 + 퍼센트 + 진행 바**를 표시합니다.
- 밝기는 화면이 완전히 검게 꺼지는 상황을 피하기 위해 최소 1%로 제한합니다.
- 가로 이동이 세로 이동보다 큰 경우에는 기존 수평 탐색이 우선하고, 세로 이동이 더 큰 경우에만 밝기/볼륨 조절로 인식합니다.
- 세로 드래그가 시작되면 임시 2배속, 수평 탐색 미리보기와 충돌하지 않도록 현재 제스처를 하나로 고정합니다.
- 세로 드래그 후 손을 떼는 동작이 단일 탭으로 오인되지 않도록 짧은 탭 억제 구간을 적용합니다.
- 화면 잠금 상태에서는 밝기/볼륨 세로 제스처도 동작하지 않습니다.

## 최근 파일

앱을 열거나 재생 화면에서 뒤로가기를 누르면 JOON Player 홈 화면에 최근 열었던 영상이 표시됩니다.

- 최근 파일은 최대 12개까지 유지합니다.
- 파일 앱에서 선택한 URL의 iOS bookmark 데이터를 로컬 `UserDefaults`에 저장해 다음 실행에서도 다시 열기를 시도합니다.
- 같은 파일을 다시 열면 최근 목록 맨 위로 이동합니다.
- 최근 목록의 휴지통 버튼으로 개별 삭제할 수 있고 **모두 지우기**도 지원합니다.
- 원본이 이동·삭제됐거나 iCloud/외장 저장장치 접근이 끊겨 bookmark를 다시 열 수 없으면 해당 항목을 목록에서 제거하고 안내합니다.
- 최근 파일 목록에는 영상 자체를 복사하지 않으며 원본 파일은 기존 위치에 그대로 둡니다.

## 영상 자르기 모드

재생 화면 상단의 **가위 아이콘**을 누르면 영상 자르기 화면을 엽니다.

### 빠른 자르기

재인코딩을 최대한 피해서 빠르게 새 파일을 만듭니다.

- 속도가 빠름
- 원본 영상 화질을 그대로 유지하기 쉬움
- 키프레임 구조에 따라 실제 시작 위치가 사용자가 고른 위치보다 약간 앞뒤로 움직일 수 있음
- MP4 / MOV / M4V는 AVFoundation 패스스루 우선
- FFmpegKitNext 연결 시 MKV / AVI / TS / M2TS / WebM / FLV 등도 스트림 복사

### 정확 자르기

영상 데이터를 다시 디코딩/인코딩해 키프레임 제약을 없애고 선택 지점에 가까운 **실제 프레임 경계**에서 자릅니다.

- MP4 / MOV / M4V는 AVFoundation 고품질 재인코딩 우선
- 그 밖의 형식은 FFmpegKitNext 연결 시 FFmpeg 재인코딩
- FFmpeg 출력은 MP4 / MPEG-4 video + AAC
- 빠른 자르기보다 오래 걸림
- 재압축 때문에 파일 크기와 화질이 달라질 수 있음
- **빠름**: AVFoundation 저용량 프리셋 또는 FFmpeg q=6 / AAC 128k
- **균형**: AVFoundation 중간 품질 프리셋 또는 FFmpeg q=4 / AAC 160k — 기본값
- **고화질**: AVFoundation 최고 품질 프리셋 또는 FFmpeg q=2 / AAC 192k

두 방식 모두 원본 파일은 수정하지 않고 새 파일을 만들며, 외부 SRT 자막은 결과 영상에 포함하지 않습니다.

## 영상 복구 / 리먹스

빠른 설정의 **영상 복구 / 리먹스**에서 현재 영상의 복구본 생성을 시도할 수 있습니다.

복구는 재인코딩이 아니라 FFmpeg 스트림 복사 방식입니다.
원본 파일은 그대로 두고, FFmpeg가 읽을 수 있는 영상·오디오·내장 자막 스트림을 새 **MKV** 컨테이너에 다시 담습니다.

복구 과정에서는 가능한 경우 손상 패킷을 건너뛰고 타임스탬프를 새로 생성해 컨테이너/인덱스/타임스탬프 계열 문제의 재생 가능성을 높입니다.

단, 이미 유실된 영상 데이터나 심하게 깨진 코덱 데이터, MP4 핵심 메타데이터가 완전히 사라진 경우까지 복원하는 기능은 아닙니다.

FFmpegKitNext가 아직 Xcode 빌드에 연결되지 않은 상태에서는 메뉴에 **연결 대기**가 표시되고 복구 버튼이 비활성화됩니다.
나중에 `ffmpegkit` 모듈을 연결하면 같은 코드에서 자동으로 활성화됩니다.

복구가 실패하면 FFmpeg의 긴 원문을 그대로 경고창에 표시하지 않습니다. JOON Player가 로그의 대표 패턴을 읽어 **파일 구조/메타데이터 문제, 코덱 정보 문제, 손상된 스트림, 저장공간 부족, 파일 접근 권한, 출력 컨테이너 문제** 등으로 요약하고 사용자가 다음에 시도할 행동을 함께 보여줍니다.

기술 로그는 복구 화면의 **기술 로그 보기**에서 별도로 펼칠 수 있고, 필요하면 복사해서 Xcode 디버깅이나 후속 점검에 사용할 수 있습니다. 이 분류는 FFmpeg 로그 패턴을 이용한 안내이며 파일 손상의 확정 진단은 아닙니다.

복구 방식은 두 단계로 선택할 수 있습니다.

- **빠른 복구**: 재인코딩 없이 영상·오디오·내장 자막을 새 MKV에 다시 담습니다. 빠르고 화질 손실이 거의 없습니다.
- **2차 재인코딩**: 빠른 복구로 스트림 복사가 되지 않을 때, 읽을 수 있는 영상·오디오를 다시 디코딩·인코딩해 새 MP4로 만듭니다. 처리 시간이 오래 걸리고 화질/용량이 달라질 수 있으며 내장 자막은 포함하지 않습니다.

저장공간 부족, 파일 권한 문제, 원본 접근 실패, MP4 moov 메타데이터 완전 손실처럼 재인코딩으로 해결되지 않는 유형에서는 자동으로 2차 복구 버튼을 권하지 않습니다.

## 자막 표시 설정

외부 SRT 자막이 연결되면 빠른 설정에서 자막 표시를 조절할 수 있습니다.

- **크기**: 60% ~ 180% 범위에서 10% 단위로 조절합니다. 가운데 퍼센트 값을 누르면 100%로 즉시 초기화됩니다.
- **위치**: 기본 / 위로 / 더 위로 세 단계로 선택합니다.
- **싱크**: 기존과 동일하게 -10초 ~ +10초 범위에서 0.1초 단위로 조절합니다.

VLCKit 4는 자막 크기를 `currentSubTitleFontScale`로 재생 중 바로 변경할 수 있습니다. 세로 위치는 VLC의 `sub-margin` 미디어 옵션을 사용하므로 위치를 바꾸면 현재 영상을 짧게 다시 열고 같은 재생 시점으로 복귀합니다. 재생 중이었다면 계속 재생하고, 일시정지 상태였다면 같은 위치에서 다시 일시정지합니다.

크기와 위치 선택은 `UserDefaults`에 저장되어 다음 영상과 다음 앱 실행에도 그대로 사용됩니다.

## 이어보기

이어보기 기록은 서버나 Supabase가 아니라 iPhone / iPad의 로컬 `UserDefaults`에만 저장합니다.

재생 중에는 약 5초 간격으로 현재 위치를 저장하고, 앱이 비활성화되거나 백그라운드로 이동할 때도 한 번 더 저장합니다.
같은 파일을 다시 선택하면 저장된 위치가 10초 이상이고 영상 끝까지 30초 이상 남아 있을 때 자동으로 해당 위치에서 재생을 이어갑니다.

영상 초반 10초 이내의 기록과 끝나기 30초 이내의 기록은 남기지 않으므로, 거의 다 본 영상은 다음에 처음부터 시작합니다.
기록은 최근 100개까지만 유지합니다.

## VLCKit 의존성

PiP를 포함한 현재 구조는 VLCKit 4의 Picture-in-Picture drawable API를 사용합니다.

```ruby
pod 'VLCKit', '4.0.0a24'
```

따라서 기존 `MobileVLCKit` 대신 `VLCKit 4.0.0a24`로 고정합니다.

## PiP

빠른 설정의 **PiP 시작**을 누르면 iOS의 화면 속 화면으로 전환합니다.

VLCKit이 PiP 컨트롤러를 준비하기 전에는 버튼이 **준비 중** 상태로 비활성화되고, 준비가 끝나면 활성화됩니다.
PiP 창에서 재생 / 일시정지 / 탐색을 하면 JOON Player의 VLC 재생 상태에도 그대로 반영됩니다.

실기기 빌드 단계에서는 Xcode의 **Background Modes → Audio, AirPlay, and Picture in Picture**를 활성화해야 합니다.
현재 저장소에는 아직 Xcode 프로젝트 파일이 없으므로 이 Capability 설정은 Mac/Xcode 프로젝트 생성 단계에서 적용합니다.

## 화면비율

빠른 설정의 **화면비율**에서 세 가지 모드를 바로 바꿀 수 있습니다.

- **원본**: 영상 고유 비율을 유지하고 전체 프레임이 보이도록 맞춥니다. 화면 비율이 다르면 검은 여백이 생길 수 있습니다.
- **화면 맞춤**: 현재 iPhone / iPad 화면 비율에 영상을 맞춰 빈 공간 없이 표시합니다. 영상 원본 비율과 화면 비율이 다르면 가로 또는 세로가 늘어나 보일 수 있습니다.
- **화면 채우기**: 영상 고유 비율을 유지한 채 화면을 꽉 채웁니다. 화면 밖으로 나가는 일부 영역은 잘릴 수 있습니다.

기기를 세로 또는 가로로 돌리면 현재 선택한 모드가 새 화면 크기에 맞춰 자동으로 다시 적용됩니다.

## 자막 자동 연결

예를 들어 아래 두 파일이 같은 폴더에 있고 파일 제공자가 형제 파일 접근을 허용하면 자동 연결을 시도합니다.

```
movie.mkv
movie.srt
```

iCloud Drive나 외부 파일 제공자의 권한 정책 때문에 같은 폴더의 SRT를 앱이 직접 읽지 못하는 경우에는 빠른 설정의 **SRT 파일 선택**으로 직접 연결할 수 있습니다.

## 화면 잠금

재생 컨트롤 오른쪽의 잠금 아이콘을 누르면 화면 조작이 잠깁니다.

잠금 상태에서는 영상 화면을 터치해도 컨트롤이 나타나지 않고, 재생바 / 10초 이동 / 재생 / 볼륨 / 설정이 작동하지 않습니다.
왼쪽 아래에 남아 있는 잠금 버튼을 누르면 즉시 해제되고 일반 컨트롤이 다시 나타납니다.

현재 화면 잠금은 JOON Player 내부의 **재생 컨트롤 잠금**이며, iPhone의 시스템 회전 잠금 설정 자체를 변경하지는 않습니다.

## 파일 처리 원칙

영상은 기본적으로 iOS 파일 앱 / iCloud Drive / 내 iPhone / 외장 저장장치에 있는 파일을 직접 선택해 재생합니다.
앱 내부로 강제 복사하지 않습니다.

## 나중에 Mac / Xcode 환경에서 시작하는 방법

1. Xcode에서 iOS App 프로젝트 생성
   - Product Name: `JOONPlayer`
   - Interface: SwiftUI
   - Language: Swift
   - iOS 17+
2. 이 저장소의 `JOONPlayer` 폴더를 프로젝트에 추가
3. 저장소 루트의 `Podfile` 사용
4. CocoaPods 설치 후 `pod install`
5. Xcode → Signing & Capabilities → Background Modes 추가
6. **Audio, AirPlay, and Picture in Picture** 활성화
7. FFmpegKitNext v9.0.0 iOS XCFramework를 로컬 빌드하여 Xcode에 연결
8. 생성된 `.xcworkspace`를 열어 실기기 빌드

## 다음 개발 순서

1. 현재 상태는 GitHub + Mac continuity 문서 기준으로 보존
2. Mac이 준비되면 `Docs/JOON-Player-Mac-Continuity.md` 순서대로 clone → XcodeGen → CocoaPods → 첫 compile
3. 첫 Simulator compile 오류를 순서대로 제거
4. Simulator 성공 뒤 실기기에서 재생·PiP·자막·제스처·자르기·복구를 통합 검증

## 설계 원칙

- Supabase 의존 기능은 최대한 후순위
- 정상 작동하는 기능은 불필요하게 건드리지 않음
- 세로 / 가로 / 화면 크기 / iPhone / iPad에 맞춰 자동 적응
- 전체화면은 영상 중심, 컨트롤은 필요할 때만 표시
- UI는 얇고 심플한 iOS 스타일
